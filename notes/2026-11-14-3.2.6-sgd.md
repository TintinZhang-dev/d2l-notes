> **In short:** 3.2.6 writes the parameter update by hand: `θ ← θ − η · grad / batch_size`, wrapped in `no_grad` so the update is not tracked, then zeros the gradient because PyTorch accumulates it. The division is there because the loss is a sum, not a mean.

## 我的问题

3.2.6 这几行在干什么？为什么不能直接用优化器？

## 第一反应

`sgd` 看着像个黑盒，参数、学习率、batch_size 三个一起传进去就完事了。

## 卡在哪

`with torch.no_grad()` 和 `param.grad.zero_()` 这两句，不知道删掉会怎样。

## 想通了

### 0. 代码原文

```python
def sgd(params, lr, batch_size):  #@save
    """小批量随机梯度下降"""
    with torch.no_grad():
        for param in params:
            param -= lr * param.grad / batch_size
            param.grad.zero_()
```

调用方式：

```python
sgd([w, b], lr, batch_size)
```

### 1. 它做的事就是一行公式

```
θ ← θ − η · ∇L / b
```

- η 是学习率 `lr`
- ∇L 是 `param.grad`
- b 是 `batch_size`

三行代码对应三个动作：取梯度、走一步、清梯度。

### 2. 为什么要除以 batch_size

因为 3.2.5 的损失函数是**求和**，不是求平均：

```python
def squared_loss(y_hat, y):
    return (y_hat - y.reshape(y_hat.shape)) ** 2 / 2
```

一批 10 个样本，返回的是 10 个平方误差叠在一起的向量。`l.sum().backward()` 之后，`param.grad` 是这 10 个梯度之和。

除以 b，才是“这一批的平均梯度”。

不除会怎样：梯度大 b 倍，等效学习率也大 b 倍。b=10 时学习率相当于 0.3，直接跑飞。

（3.3 用框架的 loss 时它默认取平均，那时候就不该再除。这就是手写版和简洁版的差异之一。）

### 3. 为什么要 no_grad

参数更新是**手动赋值**，不是网络前向计算。autograd 不该记录这次操作。

不加会报错：

```
RuntimeError: a leaf Variable that requires grad is being used in an in-place operation.
```

原因：`w` 是叶子张量，`requires_grad=True`。对叶子张量做原地运算，并且让它进入计算图，PyTorch 不允许。

`no_grad` 关掉记录，`param -= ...` 就只是普通的内存写入。

老写法是 `param.data -= ...`。绕开检查，但容易忘、容易出错。现在推荐 `no_grad`。

### 4. 为什么 grad 要手动清零

PyTorch 的梯度是**累加**的。`backward()` 不会覆盖 `grad`，而是往上加。

```python
# 不清零会怎样
第 1 批：grad = g1
第 2 批：grad = g1 + g2     <- 叠加了
第 3 批：grad = g1 + g2 + g3
```

于是参数更新量越来越大，几步之后数值爆炸。

所以每批更新完必须 `zero_()`。

为什么设计成累加：梯度累积（gradient accumulation）是常用技巧。显存不够时，跑多个小 batch 再更新一次。自动覆盖就做不到了。

### 5. 为什么传的是列表 [w, b]

`sgd` 不关心有几个参数。遍历谁就更新谁。

所以既能 `sgd([w, b], ...)`，也能传给一个有几百层的模型：`sgd(model.parameters(), ...)`。

### 6. 为什么不直接用 torch.optim.SGD

3.3 才换。这里手写，是为了让更新公式露出来。

框架的 `optim.SGD` 内部做的是同一件事，外加动量、权重衰减、梯度裁剪这些选项。看不懂 3.2.6，3.3 就只是调 API。

## 追问：sgd 到底负责什么

一句话：**它负责“照着梯度反方向走一小步”。**

### 训练循环里谁干什么

| 步骤 | 谁做 |
| --- | --- |
| 取一批数据 | `data_iter` |
| 前向算预测 | `net(X, w, b)` |
| 算误差 | `loss(pred, y)` |
| 算梯度 | `l.sum().backward()` |
| **改参数** | **`sgd(...)`** |
| 清梯度 | `sgd` 里的 `zero_()` |

`sgd` 不算梯度，也不算损失。它只做“用梯度改参数”这一件事。

### 为什么叫随机梯度下降

拆三个词：

- **梯度**：损失对参数的变化率，指出哪个方向让损失变大
- **下降**：往反方向走，损失才会变小
- **随机**：每次只用一个随机抽的小批数据，不是全量

用全量叫 batch GD，太慢。用一批叫 mini-batch，是现在的主流。“随机”说的是抽样。

### 步子大小由 lr 决定

```
w ← w − lr × grad
```

lr 太大：一步跨过谷底，来回震荡甚至发散。
lr 太小：走得太慢，跑一晚上还在半山腰。

### 实测：一步一步逼近

目标 w = 3，初始 w = 0，lr = 0.3，损失是 (w − 3)²：

```
step 0: w = 0.000, loss = 9.000, grad = -6.000
step 1: w = 1.800, loss = 1.440, grad = -2.400
step 2: w = 2.520, loss = 0.230, grad = -0.960
step 3: w = 2.808, loss = 0.037, grad = -0.384
step 4: w = 2.923, loss = 0.006, grad = -0.154
step 5: w = 2.969, loss = 0.001, grad = -0.061
最后 w = 2.9877（目标是 3）
```

每次 w 往 3 挪一点，loss 掉一个数量级。走 6 步已经到 2.99。

这就是 sgd 干的事：**反复走小步，让损失掉下去。**

### 类比

蒙眼下山。脚感告诉你哪边是下坡（梯度），你每步只挪一点（lr）。走得多了就到底了。

每批数据不同，脚感每次略有偏差，这就是“随机”的来源，也是它能跳出局部坑的原因之一。

## 追问：lr 是不是越大，学得越快

一半对。

**对的部分**：lr 大，每步位移大，同等步数下损失掉得多。

**不对的部分**：超过某个临界点，它不是“学得快”，而是根本学不动。

### 实测四组

还是那个例子：目标 w = 3，损失 (w − 3)²，初始 w = 0。

| lr | 前 6 步的 w | 结果 |
| --- | --- | --- |
| 0.1 | 0.6, 1.08, 1.46, 1.77, 2.02, 2.21 | 稳，但慢 |
| 0.3 | 1.8, 2.52, 2.81, 2.92, 2.97, 2.99 | 快且稳 |
| 0.9 | 5.4, 1.08, 4.54, 1.77, 3.98, 2.21 | 来回跳，但在收敛 |
| 1.05 | 6.3, −0.63, 6.99, −1.39, 7.83, −2.32 | 越走越远，发散 |

lr = 0.9 那行最好玩：跳跃幅度很大，但每轮都在往 3 靠。

lr = 1.05 那行已经翻出负数，两边越跑越远。

### 临界点能算出来

对二次损失：

```
w(n+1) − 3 = (1 − 2·lr)·(w(n) − 3)
```

误差每步乘 `|1 − 2·lr|`。

- 小于 1 → 收敛
- 大于 1 → 发散

所以条件就是 `lr < 1`。这里曲率 L = 2，一般写作：

```
lr < 2 / L
```

L 是损失曲面最陡方向的曲率。

### 为什么“最陡”决定上限

某个方向上曲率大（谷壁陡），同样的 lr 在那一步就会冲过头。

所以 lr 的上限由最陡的那个方向定死。可平坦方向上，这个 lr 又显得太小、走得慢。

这就是后来出现自适应方法（AdaGrad、Adam）的动机：每个参数单独调步长。

### 还跟 batch size 有关

梯度是从一批样本估出来的，本身有噪声，噪声量级大约 1/√b。

- batch 大 → 梯度准 → 敢用大 lr（经验规则：线性缩放）
- batch 小 → 梯度抖 → lr 得收着

### 实践上怎么看

不是背一个数，是看曲线：

- loss 平滑下降 → lr 合适
- loss 上下抖、降不下去 → 降 10 倍
- loss 变成 NaN 或突然暴涨 → 立刻降，或者加梯度裁剪

常见做法是 warmup（前几百步从很小的 lr 线性升上去）+ 后期衰减。因为一开始参数乱，梯度大，直接上大 lr 会炸。

### 一句话

lr 不是“学习速度”旋钮，是“步长”旋钮。

走得远比走得快重要，因为走歪了就回不来。

## 代码验证

```python
import torch

w = torch.normal(0, 0.01, size=(2, 1), requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr, batch_size = 0.03, 10

# 不加 no_grad 会报错
try:
    w -= lr * torch.ones_like(w) / batch_size
except RuntimeError as e:
    print('报错:', e)

# 正确写法
with torch.no_grad():
    w -= lr * torch.ones_like(w) / batch_size
print('更新成功, grad 还是 None:', w.grad)
```

## 还没解决的

`sgd` 里没有对 grad 为 None 做保护（某个参数这次没参与计算就会是 None）。真实训练里会遇到，书里跳过了。
