> **In short:** 3.2.6 writes the parameter update by hand: `θ ← θ − η · grad / batch_size`, wrapped in `no_grad` so the update is not tracked, then zeros the gradient because PyTorch accumulates it. The division is there because the loss is a sum, not a mean.

## 我的问题

3.2.6 这几行在干什么？为什么不能直接用优化器？

## 第一反应

`sgd` 看着像个黑盒，参数、学习率、batch_size 三个一起传进去就完事了。

## 卡在哪

`with torch.no_grad()` 和 `param.grad.zero_()` 这两句，不知道删掉会怎样。

## 想通了

### 0. 代码原文

```python
def sgd(params, lr, batch_size):  #@save
    """小批量随机梯度下降"""
    with torch.no_grad():
        for param in params:
            param -= lr * param.grad / batch_size
            param.grad.zero_()
```

调用方式：

```python
sgd([w, b], lr, batch_size)
```

### 1. 它做的事就是一行公式

```
θ ← θ − η · ∇L / b
```

- η 是学习率 `lr`
- ∇L 是 `param.grad`
- b 是 `batch_size`

三行代码对应三个动作：取梯度、走一步、清梯度。

### 2. 为什么要除以 batch_size

因为 3.2.5 的损失函数是**求和**，不是求平均：

```python
def squared_loss(y_hat, y):
    return (y_hat - y.reshape(y_hat.shape)) ** 2 / 2
```

一批 10 个样本，返回的是 10 个平方误差叠在一起的向量。`l.sum().backward()` 之后，`param.grad` 是这 10 个梯度之和。

除以 b，才是“这一批的平均梯度”。

不除会怎样：梯度大 b 倍，等效学习率也大 b 倍。b=10 时学习率相当于 0.3，直接跑飞。

（3.3 用框架的 loss 时它默认取平均，那时候就不该再除。这就是手写版和简洁版的差异之一。）

### 3. 为什么要 no_grad

参数更新是**手动赋值**，不是网络前向计算。autograd 不该记录这次操作。

不加会报错：

```
RuntimeError: a leaf Variable that requires grad is being used in an in-place operation.
```

原因：`w` 是叶子张量，`requires_grad=True`。对叶子张量做原地运算，并且让它进入计算图，PyTorch 不允许。

`no_grad` 关掉记录，`param -= ...` 就只是普通的内存写入。

老写法是 `param.data -= ...`。绕开检查，但容易忘、容易出错。现在推荐 `no_grad`。

### 4. 为什么 grad 要手动清零

PyTorch 的梯度是**累加**的。`backward()` 不会覆盖 `grad`，而是往上加。

```python
# 不清零会怎样
第 1 批：grad = g1
第 2 批：grad = g1 + g2     <- 叠加了
第 3 批：grad = g1 + g2 + g3
```

于是参数更新量越来越大，几步之后数值爆炸。

所以每批更新完必须 `zero_()`。

为什么设计成累加：梯度累积（gradient accumulation）是常用技巧。显存不够时，跑多个小 batch 再更新一次。自动覆盖就做不到了。

### 5. 为什么传的是列表 [w, b]

`sgd` 不关心有几个参数。遍历谁就更新谁。

所以既能 `sgd([w, b], ...)`，也能传给一个有几百层的模型：`sgd(model.parameters(), ...)`。

### 6. 为什么不直接用 torch.optim.SGD

3.3 才换。这里手写，是为了让更新公式露出来。

框架的 `optim.SGD` 内部做的是同一件事，外加动量、权重衰减、梯度裁剪这些选项。看不懂 3.2.6，3.3 就只是调 API。

## 代码验证

```python
import torch

w = torch.normal(0, 0.01, size=(2, 1), requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr, batch_size = 0.03, 10

# 不加 no_grad 会报错
try:
    w -= lr * torch.ones_like(w) / batch_size
except RuntimeError as e:
    print('报错:', e)

# 正确写法
with torch.no_grad():
    w -= lr * torch.ones_like(w) / batch_size
print('更新成功, grad 还是 None:', w.grad)
```

`sgd` 里没有对 grad 为 None 做保护（某个参数这次没参与计算就会是 None）。真实训练里会遇到，书里跳过了。
