> **In short:** Data is evidence about the world; an algorithm is a rule for turning evidence into a conclusion. The hard limit is information-theoretic: no algorithm can add information the data does not contain (data processing inequality). Good algorithms only look smarter because their inductive bias carries prior information from somewhere other than the sample.

## 我的问题

算法和数据的关系，是不是类似蒸汽机和煤？有没有更根本的说法？根本区别在哪？

## 第一反应

“数据是燃料，算法是引擎”，听起来挺顺。

## 卡在哪

顺归顺，但一处不对劲：煤烧完就没了，数据用完还在。那它俩到底算不算同一类关系？

## 想通了

### 类比成立的部分

1. 单独都没用。煤堆在那不会自己做功，蒸汽机没煤就是一堆铁。
2. 配套才有效。小引擎配大煤矿是浪费，大模型配劣质数据也跑不快。
3. 边际收益递减。煤多到一定程度，瓶颈转到锅炉耐压。数据多到一定程度，瓶颈转到模型容量和标注质量。

### 类比不成立的部分

1. **煤被消耗，数据不被消耗。** 煤烧一吨少一吨。数据可以复制，边际成本几乎为零。经济学上叫非竞争性：我用了不影响你用。
2. **煤同质，数据异质。** 一吨煤就是一吨煤，热值差不了几倍。一 TB 数据的价值能差几个数量级，全看分布、标注、去重。
3. **引擎效率固定，算法会变。** 蒸汽机效率由结构和工质定，加煤不会改变它。算法的行为会随数据规模改变，有些方法只有数据过了门槛才 work。
4. **数据有正反馈，煤没有。** 用户多 → 数据多 → 模型好 → 用户更多。煤挖出来不会自己变多。

### 根本区别：三层

**第一层，类别不同。**

- 数据是**关于世界的证据**，是样本，是观测。
- 算法是**从证据到结论的规则**，是过程，是映射。

一个是名词，一个是动词。放在一起比较“谁更重要”，本身就像问“砖头和图纸谁更重要”。

**第二层，作用方向不同。**

数据约束可能性，算法产生确定性。

同样一批数据，换算法就换答案：线性模型看到斜率，决策树看到切分点，kNN 看到邻居。

同样一个算法，换数据就换答案。

所以两者互相定义，不是并列的两个东西。

**第三层，也是最根本的：数据是信息，算法是压缩。**

学习要做的事，是用尽量短的假设去覆盖尽量多的观测。这叫最短描述长度（MDL）。

由此有两个硬结论：

1. **数据处理不等式**：任何算法处理，都不能增加数据里关于目标的信息量。算法只能重排、压缩、泛化，不能凭空造信息。
2. **没有免费午餐**：在完全没有结构的世界上，任何算法平均表现一样差。算法能赢，靠的是假设世界有结构。

那“好算法用更少数据”怎么解释？因为先验也是信息，只不过来源不是样本，而是人或者结构。卷积网络省数据，靠的是“图像有局部性”这条先验。

一句话收口：**算法不能突破数据的信息上限，只能逼近；数据也不能自动变成结论，必须经过假设。**

### 误差拆开看

```
泛化误差 ≈ 近似误差 + 估计误差
```

- 近似误差：假设空间太小，装不下真实规律。算法负责。
- 估计误差：样本太少，选错了。数据负责。

加数据只压后半截。前半截要靠换模型或换特征。

### 定量上的证据

1. **缩放定律。** Kaplan 2020：损失随参数量和数据量按幂律下降。Chinchilla 2022 给出可交换率，算力最优时约每参数 20 个 token。
2. **数据质量能改写曲线。** 去重、清洗、筛选后的小数据集，常打赢大而脏的。phi 系列用“教科书级”数据就是这么干的。
3. **合成数据。** 算法生成数据，再训练算法。界线糊掉，说明两者在同一套系统里，不是燃料和引擎。

### 更贴切的类比

不是煤和蒸汽机，是**矿石和冶炼**：数据要提炼，提炼完矿石还在。
