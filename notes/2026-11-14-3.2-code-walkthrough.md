## 想通了

### 1. synthetic_data：为什么要造假数据

书里先不用真实数据，因为真实数据没有标准答案。

自己按公式造一批，就知道真参数是多少：

```python
y = Xw + b + 噪声
true_w = [2, -3.4]
true_b = 4.2
```

训练完看能不能把 w、b 学回来接近这两个数。学不回来，就是代码有问题，不是数据的问题。

这是调试手段：**已知答案的题，先验证流程跑得通**。

拆开看三行：

```python
X = torch.normal(0, 1, (num_examples, len(w)))   # 1000×2，均值 0，标准差 1
y = torch.matmul(X, w) + b                       # 线性部分
y += torch.normal(0, 0.01, y.shape)              # 加噪声，原地加
```

噪声标准差 0.01 很小，所以点基本贴着平面，肉眼能看出趋势。

### 2. label 是什么

- `features` = X，输入
- `labels` = y，答案

机器学习里习惯把答案叫 label（标签）。分类里是类别名，回归里就是一个数。

`y.reshape((-1, 1))` 把它变成列向量。-1 表示这一维自动算，1000 个元素就变成 1000×1。

所以 `labels[0]` 打印出来是 `tensor([4.1538])` 这种带一对方括号的，因为它是 1×1。

### 3. d2l.set_figsize()：一行设置图大小

```python
def set_figsize(figsize=(3.5, 2.5)):
    use_svg_display()
    plt.rcParams['figure.figsize'] = figsize
```

就是把图的默认尺寸改成 3.5×2.5 英寸，顺便让图输出成 svg。

不写也行，图会大一点。

### 4. plt.scatter()：画散点

```python
d2l.plt.scatter(features[:, 1].detach().numpy(),
                labels.detach().numpy(), 1)
```

三个参数：

1. 横坐标：取 features 的第 2 列（下标 1）
2. 纵坐标：labels
3. 点的大小：1

为什么取第 2 列？因为 w 的第二个分量是 -3.4，画出来是斜向下的点云，容易看出线性关系。

为什么 `.detach().numpy()`？matplotlib 不认带梯度的张量，得先摘掉计算图再转 numpy。

### 5. random.shuffle：打乱顺序

```python
indices = list(range(num_examples))   # [0, 1, 2, ..., 999]
random.shuffle(indices)               # 原地打乱
```

为什么要打乱：

1. 数据原本可能有顺序（按时间、按类别）。不打乱，模型会学到顺序这个假规律。
2. 每个 epoch 顺序不同，梯度下降的路径更随机，不容易卡在坏点上。

注意它改的是 `indices` 本身，不是返回新列表。

### 6. yield：生成器

这是最关键的一个。

普通函数用 `return`，算完一次性给你结果。用 `yield` 的函数变成生成器：

```python
def data_iter(batch_size, features, labels):
    ...
    for i in range(0, num_examples, batch_size):
        batch_indices = torch.tensor(indices[i: min(i + batch_size, num_examples)])
        yield features[batch_indices], labels[batch_indices]
```

调用它不会执行函数体，只创建一个生成器对象。每次 `next()` 才跑到下一个 `yield`，停住，把那一批交出来。

```python
g = data_iter(10, features, labels)   # 什么都没算
X, y = next(g)                         # 才开始跑，拿到第一批
X, y = next(g)                         # 从上次停的地方继续，第二批
```

`for X, y in data_iter(...)` 就是反复 `next()`，直到 `StopIteration`。

为什么不用一次返回 list：

- 1000 条没事，100 万条全取出来会吃内存
- 按需算，拿一批训一步，内存只占一个 batch

### 7. min(i + batch_size, num_examples) 干什么

防止最后一批越界。1000 条、batch 10 正好整除；要是 1003 条，最后一批只有 3 条，切片会自己截断，但写上 min 更明确。

## 代码验证

```python
import torch, random

w = torch.tensor([2, -3.4])
b = 4.2

def make(n):
    X = torch.normal(0, 1, (n, len(w)))
    y = X @ w + b
    y += torch.normal(0, 0.01, y.shape)
    return X, y.reshape((-1, 1))

X, y = make(1000)
print(X.shape, y.shape)      # torch.Size([1000, 2]) torch.Size([1000, 1])
print(y[0])                  # tensor([4.1538]) 之类的数

# 生成器行为
def gen():
    for i in range(3):
        yield i
g = gen()
print(next(g), next(g), next(g))   # 0 1 2
```

## 每个 epoch 都会重新打乱吗

会。

训练循环长这样：

```python
for epoch in range(num_epochs):
    for X, y in data_iter(batch_size, features, labels):
        ...
```

外层每转一圈都重新调用一次 `data_iter`，函数体重跑，`random.shuffle` 也就再执行一次。

同一个生成器对象内部不会再打乱，它只按创建时那次顺序吐批次。
